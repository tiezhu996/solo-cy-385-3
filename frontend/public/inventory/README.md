# 宝宝辅食库存与消耗记录

按月龄为每个宝宝独立建立辅食食材库存：登记食材名称、数量与到期日、设置低库存下限；喂食后按实际用量扣减并自动留下消耗记录。

零依赖、纯前端页面，数据保存在浏览器本地（localStorage），不上传任何服务器。

## 本地运行

任选一种方式：

1. **直接打开**：双击 `index.html`（或拖进浏览器）即可使用，无需安装任何东西。
2. **静态服务器**（推荐，手机同局域网访问也方便）：

   ```bash
   # 任选其一，在本目录执行
   python3 -m http.server 8080
   # 或
   npx --yes serve .
   ```

   然后访问 http://localhost:8080/ 。

3. **随主项目运行**：本目录位于主前端的 `public/inventory/` 下，执行 `npm run dev` 后访问
   http://localhost:5173/inventory/ （主项目首页也有入口卡片）；Docker/Nginx 部署后路径为
   `/inventory/`。

首次打开会自动生成“小满 / 豆豆”两个宝宝和若干演示食材（覆盖正常、低库存、临期、已过期四种状态），页面底部“恢复演示数据”可随时重置。

## 功能说明

| 需求 | 实现 |
| --- | --- |
| 按月龄为每个宝宝建库存 | 添加宝宝时登记出生日期，月龄按日历月自动计算（出生当月为 0 月龄）；每个宝宝库存完全独立 |
| 登记食材名称、数量、到期日 | “食材入库登记”表单，名称/数量/到期日必填，单位可自定义（克、盒、袋…） |
| 低库存下限 | 入库时可设下限，列表中随时点“设下限”修改；库存 ≤ 下限即进入低库存组 |
| 喂食扣减 + 消耗记录 | 点“喂食扣减”输入实际用量，库存减少并生成一条带时间的消耗记录，支持撤销最近一次 |
| 切换宝宝只看该宝宝 | 顶部下拉切换，库存、分组、消耗记录都按当前宝宝过滤 |
| 拒绝非法操作并提示 | 用量/数量非正数、非数字、超过三位小数；喂食已过期食材；库存不足 —— 一律拒绝并给出具体原因和剩余量 |
| 分组展示 | 列表固定按 **已过期 → 低库存 → 临期（3 天内到期）→ 正常** 分组，组内按到期日升序 |

### 扣减校验规则（顺序即优先级）

1. 用量必须是大于 0 的数字，最多三位小数，否则提示“用量必须是大于 0 的数字”；
2. 食材已过到期日，拒绝喂食，提示具体过期日期，引导清理；
3. 用量大于当前库存，拒绝扣减，提示“当前仅剩 X”；
4. 全部通过才扣减并写消耗记录。扣到 0 允许（当顿清空），之后再扣会因库存不足被拒绝。

## 文件结构

```text
inventory/
├── index.html    # 页面结构（入库表单 / 分组列表 / 消耗记录 / 弹层）
├── styles.css    # 样式
├── core.js       # 核心逻辑：数据模型、localStorage 持久化、校验、分组（与界面解包，可被 Node 引用）

├── selftest.js   # 核心逻辑自测（node selftest.js）
└── README.md
```

## 自测

```bash
node selftest.js
```

覆盖：月龄计算、宝宝建档与切换隔离、非法数量/日期/下限拒绝、四种分组归类与排序、喂食扣减的三类拒绝（数量非法/已过期/库存不足）、扣到 0、撤销、补货、持久化。

## 数据与隐私

所有数据通过 `localStorage`（键名 `babytracker-inventory-v1`）保存在当前浏览器；清理浏览器数据会一并删除。后续若需要多端同步，可把 `core.js` 中的 `load/save` 替换为接口调用，界面层无需改动。
